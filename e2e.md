1. Сценарий: Поиск и создание кружка с настройками по умолчанию

    Цель: проверить основной пользовательский путь от команды `/start` до получения видео-кружка.

    Предусловия: все сервисы подняты; есть рабочий трек в каталоге.

    Шаги: пользователь отправляет `/start`; бот просит ввести название песни; пользователь вводит запрос; бот показывает список найденных треков кнопками; пользователь выбирает трек; бот показывает меню с опциями; пользователь нажимает `Создать кружок`; бот показывает прогресс обработки; по завершении бот отправляет видео-кружок.

    Ожидаемый результат: кружок успешно отправляется, длительность не больше 55 секунд, приложение не падает, диалог завершается корректно.

2. Сценарий: Создание кружка с пользовательским тайм-кодом (формат `мм:сс мм:сс`)

    Цель: проверить, что пользователь может явно выбрать нужный фрагмент песни.

    Предусловия: трек длиннее 40 секунд и доступен для скачивания; сервис обработки медиа работает.

    Шаги: пользователь проходит шаги поиска и выбора трека; в меню выбирает `Редактировать время`; выбирает ручной ввод интервала; вводит, например, `00:30 01:10`; бот возвращает в главное меню; пользователь нажимает `Создать кружок`; получает результат.

    Ожидаемый результат: присланный кружок содержит именно выбранный фрагмент (с 30-й по 70-ю секунду), ошибок валидации нет.

3. Сценарий: Поиск не дал результатов

    Цель: проверить поведение системы при валидном, но пустом поисковом запросе.

    Предусловия: бот и сервис поиска работают; используется редкий/случайный запрос (например, `nonexistent_track_12345`).

    Шаги: пользователь запускает диалог; вводит несуществующее название песни; бот отправляет сообщение о том, что ничего не найдено; пользователь отправляет другой запрос; бот снова выполняет поиск.

    Ожидаемый результат: бот не зависает и не завершает диалог аварийно, корректно сообщает о пустом результате и позволяет продолжить работу без перезапуска чата.

4. Сценарий: Временная недоступность сервиса поиска аудио

    Цель: проверить отказоустойчивость при падении/недоступности внешнего сервиса поиска.

    Предусловия: бот запущен, но сервис поиска временно недоступен.

    Шаги: пользователь вводит название песни; бот обращается к сервису поиска; запрос завершается ошибкой; бот отправляет сообщение "попробуйте позже"; пользователь повторяет запрос после восстановления сервиса.

    Ожидаемый результат: при ошибке пользователю показывается понятное сообщение, бот не падает, после восстановления сервиса тот же сценарий завершается успешно.

5. Сценарий: Неверный интервал времени (валидация пользовательского ввода)

    Цель: проверить защиту от некорректных тайм-кодов.

    Предусловия: выбран трек; пользователь находится в шаге ручного ввода интервала.

    Шаги: пользователь вводит `01:00 00:30` (start > end) или интервал длиннее 55 секунд; бот сообщает об ошибке валидации; пользователь вводит корректный интервал (например, `00:10 00:50`); продолжает создание кружка.

    Ожидаемый результат: некорректный ввод не приводит к созданию видео, показывается понятная ошибка; после исправления ввода сценарий продолжается штатно и кружок создается.

6. Сценарий: Обложка трека недоступна, используется стандартное изображение

    Цель: проверить резервный путь обработки при проблеме скачивания обложки.

    Предусловия: трек находится и скачивается, но endpoint обложки возвращает ошибку/пустой ответ.

    Шаги: пользователь выбирает такой трек и запускает создание кружка; бот проходит этап загрузки аудио; на этапе обложки происходит ошибка; система автоматически подставляет стандартную обложку; сборка видео продолжается.

    Ожидаемый результат: пользователь все равно получает рабочий видео-кружок, визуально со стандартной картинкой; процесс не обрывается из-за отсутствия обложки.

7. Сценарий: Ошибка на этапе создания видео

    Цель: убедиться, что при сбое создания видео пользователь получает корректную обратную связь.

    Предусловия: бот и поиск работают, но сервис обработки медиа временно недоступен или возвращает ошибку.

    Шаги: пользователь проходит поиск и выбор трека; запускает `Создать кружок`; бот начинает обработку, затем получает ошибку от сервиса обработки; отправляет сообщение об ошибке создания кружка; диалог завершается.

    Ожидаемый результат: бот не зависает, не отправляет битый файл и не продолжает "вечную" обработку; пользователь видит явное сообщение об ошибке и может начать заново.

8. Сценарий: Недоступность сервиса логирования (БД), но функциональность для пользователя сохранена

    Цель: проверить, что логирование не ломает основной продуктовый путь.
    
    Предусловия: сервис БД недоступен, остальные сервисы работают.

    Шаги: пользователь запускает бота и выполняет поиск песни; бот пытается залогировать действие и получает ошибку; затем пользователь выбирает трек и создает кружок; на этапе создания снова возникает ошибка логирования, но обработка медиа продолжается.

    Ожидаемый результат: пользовательский сценарий выполняется до конца и кружок отправляется; проблема логирования остается внутренней технической ошибкой и не блокирует основной функционал.

9. Сценарий: Параллельная работа нескольких пользователей

    Цель: проверить изоляцию пользовательских сессий и корректность при конкурентной нагрузке.

    Предусловия: 2 пользователя; все сервисы подняты.

    Шаги: пользователи одновременно запускают `/start`, ищут разные треки, задают разные тайм-коды и запускают создание кружка; у каждого пользователя свои входные данные.

    Ожидаемый результат: каждый пользователь получает только свой кружок; нет путания состояний (чужих треков, тайм-кодов, результатов), нет массовых падений сервиса при параллельной обработке.

10. Сценарий: Полный цикл повторного использования (создать второй кружок без перезапуска бота)

    Цель: проверить стабильность длительной сессии и корректный сброс состояния между задачами.

    Предусловия: пользователь уже успешно создал один кружок.

    Шаги: после первого результата пользователь выбирает `Найти новую песню`; выполняет новый поиск, выбирает другой трек, ставит новые настройки времени и снова запускает `Создать кружок`; получает второй результат в этом же чате.

    Ожидаемый результат: второй цикл проходит независимо от первого, старые параметры не "протекают" в новый запуск, оба кружка корректные, повторное использование бота не требует ручной очистки или перезапуска.
